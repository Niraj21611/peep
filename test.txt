UI COMPONENT RULE:

Use shadcn/ui as the primary component library.

Before creating a custom UI component, check whether an appropriate shadcn/ui component already exists.

Prefer composing shadcn/ui primitives rather than creating duplicate components.

Use Tailwind CSS for styling and customization.

Use Lucide React for icons.

Do not introduce another UI component library.

Keep generated shadcn primitives inside:

src/components/ui/

Keep application-specific components inside their respective feature folders.

Now implement the Recurring Transactions feature.

This feature is extremely important because it replaces repetitive manual entries from the user's Excel workflow.

The user currently has recurring expenses such as a daily commute where the same expense may occur repeatedly.

The system should allow the user to define a recurring transaction rule.

EXAMPLE:

Name:
Daily Commute

Amount:
77

Type:
Expense

Category:
Transport

Frequency:
Weekdays

Start Date:
01-Oct-2026

End Date:
Optional

The system should be able to generate the corresponding actual transactions.

SUPPORTED FREQUENCIES:

- Daily
- Weekdays
- Weekly
- Monthly
- Yearly
- Custom

IMPORTANT ARCHITECTURE:

Do not simply insert infinite future transactions.

RecurringTransaction represents the RULE.

Transaction represents an ACTUAL financial event.

Keep these concepts separate.

Each generated transaction should retain a reference to the recurring transaction that generated it where appropriate.

DUPLICATE PROTECTION:

The system must never generate the same recurring occurrence twice.

Design an appropriate uniqueness/idempotency strategy.

USER INTERFACE:

Create a recurring transactions page containing:

- active recurring rules
- inactive recurring rules
- add recurring transaction
- edit
- activate/deactivate
- delete

Display:

Name
Amount
Type
Category
Frequency
Next occurrence
Status

SERVER-SIDE GENERATION:

Implement a reusable server-side function that can generate due recurring transactions.

For example conceptually:

generateDueRecurringTransactions()

It must:

1. Find active recurring rules
2. Determine due occurrences
3. Check whether an occurrence already exists
4. Create missing transactions
5. Update the recurrence state safely

Do not rely on client-side JavaScript timers.

The generation mechanism should be designed so that it can later be triggered by:

- application access
- scheduled job/cron
- manual "Generate Due Transactions" action

For the initial implementation, provide a safe manual/server-trigger mechanism.

Do not introduce an external cron service yet.

IMPORTANT:

Do not automatically create historical transactions incorrectly.

Respect the recurrence start date and optional end date.

Do not create occurrences after the end date.
