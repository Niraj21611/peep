UI COMPONENT RULE:

Use shadcn/ui as the primary component library.

Before creating a custom UI component, check whether an appropriate shadcn/ui component already exists.

Prefer composing shadcn/ui primitives rather than creating duplicate components.

Use Tailwind CSS for styling and customization.

Use Lucide React for icons.

Do not introduce another UI component library.

Keep generated shadcn primitives inside:

src/components/ui/

Keep application-specific components inside their respective feature folders.

Now implement the complete Category Management feature.

The primary requirement is:

ADDING A NEW CATEGORY MUST NOT REQUIRE ANY CODE CHANGES TO THE DASHBOARD, TRANSACTIONS, BUDGETS, OR OTHER FEATURES.

Categories are database-driven.

FEATURES:

1. List categories
2. Create category
3. Edit category
4. Activate/deactivate category
5. Delete category where safe
6. Filter by income/expense/both
7. Prevent duplicate category names for the same user

CATEGORY TYPES:

- INCOME
- EXPENSE
- BOTH

The UI should clearly distinguish active and inactive categories.

IMPORTANT DELETE RULE:

If a category is already referenced by transactions or budgets, do not blindly delete it.

Instead:

- either prevent deletion and explain why
- or recommend deactivation

Do not cause orphaned financial records.

SERVER ACTIONS:

Create dedicated server actions for:

- createCategory
- updateCategory
- toggleCategoryStatus
- deleteCategory if safe

Validate all inputs with Zod.

DATABASE:

All category operations must be scoped to the authenticated user.

UI:

Create a professional category management page.

Include:

- category list/table
- add category button
- edit action
- activate/deactivate action
- appropriate confirmation dialog
- empty state
