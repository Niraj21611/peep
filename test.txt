UI COMPONENT RULE:

Use shadcn/ui as the primary component library.

Before creating a custom UI component, check whether an appropriate shadcn/ui component already exists.

Prefer composing shadcn/ui primitives rather than creating duplicate components.

Use Tailwind CSS for styling and customization.

Use Lucide React for icons.

Do not introduce another UI component library.

Keep generated shadcn primitives inside:

src/components/ui/

Keep application-specific components inside their respective feature folders.

SECURITY:

Ensure:

- password hashes never reach client components
- user ownership is verified server-side
- client-provided user IDs are never trusted
- server actions validate authentication
- server actions validate input
- cookies are secure in production
- secrets are not committed
- environment variables are properly documented

MONEY:

Audit all financial calculations.

Ensure:

- no unsafe floating point arithmetic
- consistent currency handling
- consistent rounding
- dashboard totals match transaction totals
- budget calculations match transaction calculations

DATABASE:

Review indexes and uniqueness constraints.

Ensure queries are appropriately scoped to the authenticated user.

PERFORMANCE:

Avoid fetching huge transaction datasets unnecessarily.

Move aggregation logic to server/database-side operations where appropriate.

UI:

- loading state
- success state
- error state
- empty state
