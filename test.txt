UI COMPONENT RULE:

Use shadcn/ui as the primary component library.

Before creating a custom UI component, check whether an appropriate shadcn/ui component already exists.

Prefer composing shadcn/ui primitives rather than creating duplicate components.

Use Tailwind CSS for styling and customization.

Use Lucide React for icons.

Do not introduce another UI component library.

Keep generated shadcn primitives inside:

src/components/ui/

Keep application-specific components inside their respective feature folders.

Now implement the complete Dashboard.

Use the provided Excel Dashboard screenshot as the functional reference, but build a modern responsive finance dashboard rather than copying the spreadsheet layout.

The dashboard must calculate everything from the database.

Do NOT hardcode financial values.

TOP FILTER:

Provide:

- Start Date
- End Date

Default to the current month.

All dashboard statistics must respond to the selected date range.

SUMMARY CARDS:

Display:

1. Total Income
2. Total Expenses
3. Net Savings
4. Savings Rate

Calculations:

Net Savings = Total Income - Total Expenses

Savings Rate =
if Total Income > 0:
Net Savings / Total Income * 100
otherwise 0

EXPENSE BY CATEGORY:

Display a category breakdown for the selected date range.

Use:

- category name
- total expense

Categories with zero spending can be omitted from the chart.

Create a donut/pie chart using Recharts.

MONTHLY SUMMARY:

Display monthly:

- Income
- Expenses

for a useful historical period.

Create a chart comparing income vs expenses.

The chart should be generated dynamically from transaction data.

ADDITIONAL USEFUL INFORMATION:

Include:

- highest spending category
- largest transaction
- transaction count
- budget overview for the selected month

Do not make the dashboard unnecessarily crowded.

RESPONSIVENESS:

Desktop:
- summary cards in a row
- charts arranged efficiently

Mobile:
- cards stack
- charts resize
- tables become scrollable or responsive

PERFORMANCE:

Do not fetch every transaction into the browser just to perform calculations there.

Perform aggregations on the server/database layer where practical.

Create reusable server-side query functions for dashboard statistics.

Keep dashboard calculation logic separate from UI components.

For example:

src/lib/finance/

could contain reusable functions such as:

- getDashboardSummary()
- getExpensesByCategory()
- getMonthlySummary()
- getBudgetSummary()

Do not put complex financial calculations directly inside React components.

After implementation:

- verify date filters
- verify income calculation
- verify expense calculation
- verify savings
- verify savings rate
- verify category chart
- verify monthly chart
- verify empty states
- verify responsive layout
- run lint/typecheck/build
